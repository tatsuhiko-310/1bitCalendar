# 1bit Calendar 引き継ぎ資料

Claude(チャット)で作ってきた「1bit Calendar」を Claude Code に移すための資料です。
成果物は単一のHTMLファイル `dither-calendar.html`(約1,190行、外部ライブラリなし)です。

## 1. プロジェクト概要

写真を1bitのドット(ディザリング)にして、カレンダー入りのスマホ壁紙を作るWebサービス。すべてブラウザ内(Canvas)で完結し、サーバー処理はありません。

- 公開中のArtifact(自分専用): https://claude.ai/artifact/SXT94AJtR7gdkxZpQPKqL3
- 想定する使い方: スマホで開き、写真を選び、カレンダーを配置し、PNGで保存して壁紙にする
- ユーザーはスマホ(Androidのアプリ版Claude)で動作確認していて、「PCモード」表示でも確認している

## 2. 現在の機能(最終状態)

### 写真
- 写真の読み込み(長辺2400pxに縮小して保持)。起動時はサンプル画像が入っている
- ディザ方式: ベイヤー 2×2 / 4×4 / 8×8、フロイド・スタインバーグ、アトキンソン、しきい値
- ドットの大きさ(1〜16px)、明るさ、コントラスト、明暗反転、写真の拡大
- トリミング: 専用の全画面画面で枠を指定。縦横比は 自由 / 1:1 / 3:4 / 9:16 / 画面(出力サイズと同じ比率)。「全体」「キャンセル」「適用」。「トリミング解除」で元に戻す。常に元の写真を基準にするので何度でもやり直せる

### カレンダー
- 年月の切り替え、今月に戻す
- レイアウト7種: グリッド / 縦リスト / 2列リスト / 縦横入れ替え / ビッグ月 / 1行 / 数字のみ
- フォント7種: ドットゴシック、Press Start 2P(英数のみ)、VT323、Space Mono、しっぽり明朝、デラゴシック、油性マジック(Google Fonts)
- 週の始まり(日/月)、言語(日本語/English)、大きさ
- 「枠」と「背景」は別々のON/OFF
- 壁紙の外にはみ出さない(はみ出しそうになると自動で内側に押し戻す。壁紙より大きい場合だけ中央に置く)

### 配置
- プレビュー上のドラッグ: カレンダーの上ならカレンダー、それ以外は写真が動く
- 2本指ピンチ / マウスホイールで拡大縮小(掴んでいる対象に作用)
- スナップ(それぞれON/OFFできる):
  - 横軸の中央にスナップ(カレンダー・写真とも)
  - カレンダーと写真の辺をそろえる(左・右・上・下の同じ側の辺。ガイドは赤い点線)

### 色
- ドットの色 / 背景の色 / 「色を反転」ボタン
- テンプレート(プリセット8種)
- カレンダーの色は、常にドットの色と同じ(固定)

### 出力・確認
- 画像サイズ: iPhone(1179×2556)、iPhone Pro Max、Android(1080×2400)、iPad、PC、正方形
- 「PNGで保存する」(保存まわりは下の「環境依存」を参照)
- 「全画面」ボタン(プレビュー右上に固定): 壁紙を画面いっぱいに表示。タップ・Escで閉じる
- 「ロック画面の時計を重ねて確認」(プレビューと全画面のみ。保存画像には入らない)。表示は大きな時計だけで、現在時刻に連動

### サイト自体のUI
- ヘッダーは「1bit Calendar」の文字だけ
- サイトの色は、選んでいる配色に連動する(下の「UIの色の仕組み」)

## 3. 削除・変更した機能(経緯。再追加しないこと)

| 項目 | 経緯 |
|---|---|
| 今日のハイライト | 不要と言われて削除 |
| カレンダーの色の選択 | 「ドットと同じで固定」にして、色選択とチェックを削除 |
| 好きな色からテンプレートを作成 | 追加後に「削除」と言われて全削除(7種類の配色理論ベースの自動生成) |
| ロック画面シミュレーションの装飾 | 最初はステータスバー・日付・ショートカット付きだったが「画像を元にしすぎ。時計だけでいい」で時計のみにした |
| ヘッダー | 一度削除し、その後「1bit Calendar とだけ書いて」で再追加 |
| 「全画面で見る」の位置 | パネル内だとスクロールで隠れるため、プレビュー右上の固定ボタンに移動 |
| 「地の色」の呼び方 | 「背景の色」に統一 |

## 4. 技術構成

### 全体
- 単一HTML。`<style>` と `<script>`(IIFE)がファイル内にある。ビルド・依存なし
- 外部リソースはGoogle Fontsのみ(DotGothic16 / Press Start 2P / VT323 / Space Mono / Shippori Mincho / Dela Gothic One / Yusei Magic)
- localStorage等の保存は使っていない(リロードで設定は初期化される)

### 状態 `S`
`S.W / S.H`(出力サイズ)、`S.src`(表示中の写真Canvas)、`S.orig`(読み込んだ元の写真)、`S.crop`(トリミング範囲)、`S.photo {x, y, scale}`(中心座標は0〜1の正規化、scaleは出力幅に対する倍率)、`S.dither {algo, px, bright, contrast, invert}`、`S.cal {show, x, y, size, year, month, style, weekStart, lang, font, frame, bg}`、`S.color {ink, paper, cal, same}`、`S.snap`、`S.snapEdge`、`S.lockSim`、`S.calBox`(当たり判定、影込み)、`S.calRect`(実際の枠)。

### 描画パイプライン(`render(guides)`)
1. 背景(paper色)を塗る
2. `renderPhoto()`: 写真を低解像度Canvas(幅 = W / ドットの大きさ)に描く → グレー化 → 明るさ・コントラスト・反転 → ディザ → ドット色のピクセルだけを別Canvasに書く → 最近傍補間で拡大して本体Canvasに描く
3. `drawCal()`(グリッド・縦リスト)または `drawCalAlt()`(他5種)でカレンダーを描く
4. ドラッグ中だけ、カレンダーの外枠ガイドとスナップのガイド線を描く(`guides`がtrueのときのみ。保存時は常にfalse)

### 主な関数
- `bayerMatrix(n)`、`renderPhoto()`、`makeSample()`
- `calMetrics()` / `drawCal()`、`drawCalAlt()`、`clampCalPos()`(はみ出し防止。計算時にS.cal.x/yを書き換える)
- `edgeSnap()` / `photoRect()`(辺のスナップ)
- `applyTheme()`(サイトの色)、`syncUI()`(Sの値をUIに反映。毎回 `applyTheme()` も呼ぶ)
- `openCrop() / applyCrop() / drawCrop()`、`makeLock() / placeLock() / placeFsLock()`、`openFs() / closeFs()`
- `fit()`(プレビューCanvasの表示サイズ計算)

### UIの色の仕組み(重要)
- サイトの色は **ドットの色と背景の色の2色だけ**。3色目を作らない方針(過去に3色になって修正した)
- `applyTheme()` が `:root` に `--bg`(=背景色)、`--fg`(=ドット色)、`--panel`(=背景色)、`--mute`(=ドット色)、`--on-fg`(=背景色)、`--ink`、`--paper` を設定する
- ドットと背景のコントラスト比が3未満のときだけ、読めるようにドット色(UI用)の明るさを調整する
- 操作パネル `.panel` は色を反転している(`.panel` 内で `--fg:var(--paper)` などを上書き)
- ダークモード用のCSS変数も残っているが、`applyTheme()` のインライン指定が優先される

### レイアウト
- モバイル: ヘッダー(44px)の下に、固定(sticky)のプレビュー(画面高の46%)、その下にパネル
- 860px以上(PCモード): 2カラムのグリッド。プレビューは左、パネルは右(400px)で、パネルは縦中央に配置し、画面より高いときはパネル内でスクロール
- ボタン類は最小44px。影は「ハードシャドウ」(ぼかしなしのオフセット)、フォントはDotGothic16

## 5. 環境依存の注意(Artifact → 通常のWebサイト)

Artifact環境で動かすための記述が一部あります。Claude Codeで通常のサイトにするときは差し替えてください。

1. **画像の保存**: 現在は `window.claude.use('downloads')` が使えるときだけ `dl.save({filename, data})` で保存し、使えなければ画像をオーバーレイ表示して「長押しで保存」にしている(`#save` のクリック処理)。通常のサイトでは `canvas.toBlob` → `URL.createObjectURL` → `<a download>` のクリックに置き換えるのが素直。モバイルでの挙動は要確認
2. **Google Fonts**: `<link>` で読み込み。Artifactの公開ページではCSPで許可されたホストのみ使えた。通常のサイトなら制約なし。フォント選択時は `document.fonts.load()` で読み込みを待ってから再描画している
3. **ファイル読み込み**: `FileReader.readAsDataURL` を使っている(Artifactで `blob:` が使えるか不明だったため)。通常のサイトなら `createImageBitmap` や `URL.createObjectURL` でもよい
4. `<meta viewport>` は `viewport-fit=cover`、safe-area対応のpaddingあり

## 6. 既知の課題・未検証

- **保存まわりは実機で未検証**(Androidでの保存、長押し保存の動作)。最優先で確認してほしい
- 全画面表示: `requestFullscreen` が使えない環境(iPhoneのSafari等)では、ページ全体を覆う表示にフォールバックする。実機未確認
- ベイヤーのパターンは出力Canvasの座標に固定されているため、写真をドラッグするとドットがちらつく(仕様)
- 毎フレーム、出力サイズ全体(例: 1179×2556)で再描画している。低性能端末でドラッグが重い可能性
- 「ピクセル」フォント(Press Start 2P)は日本語を含まないので、曜日の漢字はフォールバックのDotGothic16になる。フォントごとの文字幅補正は係数で調整していて、見た目の確認は不十分
- カレンダーのレイアウトによっては、大きさ1で長く縦に伸びるものがある(縦リスト等)。大きさスライダーで調整する前提

## 7. 整理したい箇所(リファクタ候補)

削除済みの機能の残骸が残っています。動作には影響しませんが、整理を推奨します。

- CSS: `.schemes` / `.sch` / `.sch:active` / `.schsw`(テンプレート自動生成の残り)、`input[type=color]:disabled`、`.lk-carrier` / `.lk-sig` / `.lk-bat` / `.lk-lock` / `.lk-date` / `.lk-btn` / `.lk-pill`(ロック画面の装飾の残り)
- JS: `LK` 定数(ロック画面のSVG)、`partner()`(テンプレート自動生成用。`applyTheme()`は使っていない)、`S.color.cal` / `S.color.same`(カレンダーはドット色固定なので不要。`drawCal`・`drawCalAlt`の `S.color.same ? S.color.ink : S.color.cal` を `S.color.ink` に簡略化できる)、プリセット選択時の `S.color.cal = ink`
- フォント文字幅の係数が2か所に重複: `drawCal` 内の `FK` と、`drawCalAlt` 用の `FKS`。1つにまとめる
- `drawCal`(グリッド・縦リスト)と `drawCalAlt`(他5種)で、枠・背景・影の描画コードが重複している。1つの関数に統合するとレイアウト追加が楽になる
- 単一ファイルが大きくなっているため、必要なら CSS / JS を分割(ビルドなしでESモジュールにするなど)

## 8. 作業の進め方(これまでのやり取りから)

- ユーザーは日本語。要望は短い箇条書き(「機能追加」「機能調整」「機能削除」の見出し)で来ることが多い
- スマホのアプリで使っているため、返答は短く、結果と要点だけが好まれている。UI上の説明文は最小限にする(「テンプレートという項目テキストはいらない」など、余計な見出しや文言を嫌う)
- 余計な装飾より、2色の1bitらしい見た目(ドット、ハードシャドウ、2色のみ)を重視
- 参考画像をスクリーンショットで渡して指示することがある(赤い丸や矢印で位置を示す)。指示が曖昧なときは一番自然な解釈で進めて、解釈を一言添えると良い
